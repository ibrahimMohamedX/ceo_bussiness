# PROJEX — Firestore Data Model

## 1. Design Rules

- IDs are generated by Firestore unless a stable slug is explicitly required.
- Keep human-readable slugs separate from document IDs.
- Store bilingual business content as `{ en, ar }` when the same entity exists in both languages.
- Store timestamps with Firestore `Timestamp`.
- Prefer `storagePath` over permanently storing signed/download URLs in business documents.
- Store ordering explicitly for manually curated lists.
- Every publishable document has a predictable status.

## 3. Admin

```ts
admins/{adminId}
{
  uid: string,
  email: string,
  displayName?: string,
  role: 'super_admin' | 'admin' | 'editor' | 'support',
  active: boolean,
  createdAt: Timestamp,
  updatedAt: Timestamp,
  lastLoginAt?: Timestamp
}
```

Firebase Auth remains the source of identity. Firestore stores application role/permissions metadata.

### Multiple project images

A project MUST NOT be limited to a single image.

Use a subcollection:

```text
projects/{projectId}/media/{mediaId}
```

Each project can therefore have:

- 1 cover image
- multiple gallery images
- optional diagrams
- optional UI screenshots
- optional case-study visuals
